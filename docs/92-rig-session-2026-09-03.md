### Two consequences that need code changes

1. **Power ceiling dropped.** The new dev card reports **default 200 W / max 210 W / min
   100 W** (the previous card allowed 250 W). The 2026-08-29 Dalí booth measurement leaned on
   248–249 W on its heavy views to hold 90 fps, so **that verdict must be re-measured on this
   card** before it is trusted again. `vr-power-watchdog` logic is unchanged: `power.conf`
   `GPU_LIMIT_PCT=100` now means 210 W live, 100 W at rest.
2. **The headset's DisplayPort connector moved.** On the previous card the G2 enumerated as
   `card0-DP-1`; on this card it is **`card0-DP-3`**. `jack-in-wayland.sh` and `preflight.sh`
   detect the HMD by `non-desktop=1` + EDID fingerprint, so they are **unaffected** (preflight
   step 3 = READY, verified live). But several things hardcode `DP-1` and are now wrong on this
   card — a concrete worklist for the "hardcoded assumptions" item in `docs/91`:
   - `scripts/status-dashboard.py` `drm_status()` lists only `DP-1/DP-2/HDMI-A-1/HDMI-A-2`, so
     the headset connector is invisible in the access panel.
   - `scripts/verify-bpc.sh`, `scripts/verify-override.sh`, `scripts/collect-nv.sh` read
     `card0-DP-1/{status,edid}` directly.
   - The sudoers grants (`docs/68`) allow `cat card0-DP-1/{edid,status}` specifically.
   Fix: auto-detect the non-desktop connector (the same way `jack-in-wayland.sh` already does)
   instead of naming a port, and widen the sudoers grant to the detected connector.

## Video decode benchmark (new tooling + result)

`scripts/decode-bench.sh` (machine-agnostic, no config, no sudo) and
`scripts/gpu-pacing-baseline.sh` were added and run. Full result and interpretation in
`docs/90`. Headline: **the VR180/360 library is AV1, not HEVC**; the Ampere-class dev card
hardware-decodes 8K60 AV1 at ~2×, the **Pascal-class everyday card has no AV1 hardware decoder
at all** (falls to marginal software decode) but handles 8K HEVC fine. So a Pascal card is a
dead end for the AV1 library unless the content is transcoded to HEVC, which both cards decode.

## apt / system update status

- **everyday box**: fully current, 0 upgradable, kernel already 6.12.107.
- **dev rig**: 33 upgradable — security updates plus the kernel 6.12.101 → 6.12.107. The
  patched NVIDIA 595 packages are **not** in the upgrade set (Debian ships no newer 595), so a
  plain `apt upgrade` does not touch the patched driver. The kernel bump triggers a DKMS
  rebuild of the 595 module for the new kernel; the 4 `PATCH[]` entries re-apply automatically.
  `pre-update-check.sh` is green (4 patches applied, rollback kernel 6.12.94 has a real DKMS
  build). Follow `docs/24` exactly: upgrade → reboot → `post-update-verify.sh` → **physical
  90 Hz check with the headset on** before trusting it. Do not purge old kernels until the new
  one is proven — that is the rollback.
